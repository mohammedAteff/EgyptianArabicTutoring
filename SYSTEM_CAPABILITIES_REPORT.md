# System Capabilities and Architecture Report

**Snapshot:** 2026-09-25, local checkout commit 8a5463b. **Scope:** repository and local BoltLanding database only. The earlier Hostinger deployment is described in PROJECT_STATUS.md, but this report did not independently inspect the live server or production data. This document is descriptive, not a release approval. Examples in the attached Website Audit.md were treated as proposed questions, not as implementation evidence.

## 1. Executive System Profile & Runtime Environment

- **Application:** Egyptian Arabic with Abdallah; PHP requirement ^8.4.1, Laravel 13.32.0 (installed), Livewire 4.4.5, Blade/Alpine.js, Tailwind CSS 4, Vite 8.3.0. Evidence: composer.json, composer.lock, package.json, package-lock.json, app/Livewire/BookingWizard.php, resources/views.
- **Local persistence observed:** Laravel mysql driver to MariaDB 10.11.18, database bolt_landing on 127.0.0.1:3307. All 64 application tables inspected from the live local schema are InnoDB; 44 migrations report Ran. This does not prove the production DB version or its latest rows. Primary keys are predominantly unsigned BIGINT IDs, with separate UUID/string identity and idempotency columns. Evidence: artisan db:show/db:table/migrate:status; database/migrations.
- **Transaction isolation:** A read-only local query returned MariaDB GLOBAL=REPEATABLE-READ and SESSION=REPEATABLE-READ. App\Domains\Database\Services\DatabaseCapability temporarily sets its MySQL/MariaDB transaction connection to READ COMMITTED and restores that prior session level; it does not change the server default. The production server's default was not independently queried. Production write paths fail closed unless configured reconciled vendor/version match the detected server.
- **Scheduling resource:** booking_calendar_locks.lock_date is an existing-or-created business-date mutex, acquired in deterministic order over buffer-expanded intervals before conflict checking. Booking/hold/credit operations additionally lock their corresponding rows. A range query alone is not relied upon to serialize empty slots. Evidence: App\Domains\Availability\Services\AvailabilityService, App\Domains\Database\Services\DatabaseCapability.
- **Authentication and payments:** Separate administrator web guard and low-assurance student passwordless/DOB-and-identifiers guard. No paid OTP or third-party auth SDK appears in direct dependencies or current auth routes. Payment and refund records are manually administered; there is no PayPal webhook/payment capture route. These are codebase observations, not claims about external services.
- **External dependencies:** MaxMind GeoIP database/client, optional trusted-proxy country header; optional S3-compatible offsite backups; SMTP configured by environment; private lesson-room URL configured by owner. The local .env.example contains placeholders and is not a production-readiness proof.
- **Frontend boundary:** Vite builds the CSS/fonts bundle; local build succeeded. Dynamic behavior also lives in Livewire, Alpine directives, and Blade. No standalone SPA frontend is present.

## 4. State Machines, Lifecycles & Business Logic Invariants

| Entity | Persisted states and verified transitions | Important side effects / guard |
| --- | --- | --- |
| Booking | status is VARCHAR, not a DB enum. Current services create confirmed; confirmed can be rescheduled without changing status, cancelled, completed, or marked no_show. Legacy/held/pending values may exist but cancellation/rescheduling services reject non-confirmed. | Reschedule writes session_reschedules and admin_reconfirmation_needed=true, with no ledger mutation. Confirmed cancellation is idempotent; it restores one credit only if a consumed entry exists. Admin attendance transitions lock booking rows. Sources: BookingService.php, RescheduleService.php, CancellationService.php, Admin/BookingController.php. |
| Hold | active → released/expired, or used by final booking. | Ten-minute configurable expiry; visitor/session/hold-token binding; conflict queries ignore expired holds. The scheduled cleanup **marks** expired rows; it does not delete expired/released rows. BookingHoldService.php and CleanupExpiredHoldsCommand.php. |
| Student identity | verified, legacy_unverified, merged (DB enum). | Auth only accepts verified/non-trashed; merge sets target and soft-deletes secondary; privacy workflow redacts personal fields while preserving relational history. StudentIdentityService.php, StudentMergeService.php, StudentPrivacyService.php. |
| Form | draft, published, archived (DB enum); active_version_id and published_version_id are distinct. | An active version with first draft/submission becomes frozen (FormVersion::isFrozen); later edits fork a version. Parent lock_version/base-version mismatch yields HTTP 409. Published pointer protects student-visible content until publish. FormBuilderService.php and FormSubmissionService.php. |
| Submission | draft, submitted (DB enum), revision number increases on changes. | Student/version ownership and assignment rechecked under locks; hidden conditional answers pruned; every save writes a revision snapshot. Editing submitted answers depends on can_edit_after_submission. |
| Student package | active, completed, expired, cancelled (DB enum). | Eligible active packages are locked, sorted by expiration then creation/id; credits are SUM(credit_change), not a mutable balance column. |
| Article/blog post | draft, published, archived (DB enum). | Optimistic lock_version, previous published snapshot on update, reserved old slug and 301 redirect, sanitized body. ArticleService.php and ArticleController.php. |

**Ledger worked example:** A 10-session package creates package_grant +10. One student booking appends session_consumed −1, leaving 9. A valid cancellation appends cancellation_restore +1, returning to 10; replay cannot add a second restoration because of the unique (booking_id, entry_type) index and service idempotency. A separate $100 recorded payment followed by a $70 refund leaves at most $30 refundable on that payment; a competing $40 refund must be rejected under payment/package/refund locks. This is the implemented arithmetic in StudentLedgerService.php and the MariaDB uniqueness constraints, not a claim that the full suite passed today.

## 5. Core Engine Mechanics & Defensive Concurrency Architecture

1. **Display and identity:** TimezoneService validates IANA IDs, converts canonical instants to UTC and handles DST gap/fold ambiguity. TimezoneDisplayService resolves city/country/offset; BookingWizard::selectTimezone refreshes all rendered slot/hold state. The customer's zone affects presentation, not the stored UTC appointment.
2. **Authoritative slot:** AvailabilityService generates recurring/exception-filtered slots with notice, horizon, session duration, buffers, bookings and active holds. SlotResolver::issue encrypts resource/date, session type, UTC start/end, selected timezone, visitor owner, policy fingerprint and ten-minute expiry. SlotResolver::resolve decrypts and re-generates the same day's available slots before accepting a submitted identity.
3. **Lock order:** DatabaseCapability sets a connection's transaction isolation to READ COMMITTED. AvailabilityService::acquireCalendarDateLocksForIntervals creates/locks actual booking_calendar_locks rows in sorted business-date order, including buffer-adjacent dates. BookingHoldService, BookingService, StudentBookingService, RescheduleService and CancellationService use this mutex before final conflict checks or mutation. Student booking additionally locks student/package/ledger tiers. The unique idempotency key is a second replay guard, not the overlap constraint.
4. **Public versus student booking:** Public BookingWizard requires a real visitor/session-bound hold and then BookingService::createPublicBooking finalizes it. StudentBookingService consumes one eligible package credit in the same transaction as the confirmed booking; public intake is intentionally credit-free. Do not import the attachment's illustrative UnifiedBookingTransactionService: it does not exist here.
5. **Contacts and identity:** ContactService normalizes email and merges associated bookings/resource records under transaction; StudentIdentityService separately normalizes student name/email/phone. Students can remain unverified from legacy backfill and are not silently authenticated.
6. **Forms:** FormValidationService limits question types/regex/conditional depth (max 3), detects cycles, validates submitted values and prunes invisible answers. FormBuilderService locks form/version for updates and forks frozen versions. FormSubmissionService locks form/student/submission and writes current form_answers plus immutable snapshots. Admin/FormController streams CSV in chunks and neutralizes leading spreadsheet formula characters.
7. **Analytics/CMS/ops:** AnalyticsService allow-lists client events and metadata; TrackVisitorSession and GeoIpService handle first-party identity and trusted country detection. AggregateDailyAnalyticsCommand writes durable Cairo-day rollups. ArticleService and RichTextSanitizer use HTMLPurifier and same-origin storage-image checks. BackupService archives SQL plus public/private storage, with optional offsite replication and checksum manifest.

**Proof boundary:** tests/Feature/MariaDbConcurrencyVerificationTest.php and BufferExpandedConcurrencyLockTest.php use separate PDO connections/worker processes, not only sequential calls. They pass in isolation today. The first full run failed on shared test-state/cleanup errors; after focused test-database reset, the second full run passed. No fresh load test against the live host was performed.

## 7. JSON Payloads, Data Structures & Serialization Schemas

These are implementation contracts observed in model casts, validators, and service writes; nullable JSON fields may be null, and unlisted optional keys are not guaranteed to exist.

- **form_questions.conditional_logic:** nullable object with logic_version=1, mode='all'|'any', conditions array of at most 20 objects. Each condition has question_key (another form question), operator in {equals, not_equals, contains, not_contains, in, not_in, greater_than, less_than, is_answered, is_not_answered}; value is consulted by comparison operators and may be absent for answered predicates. Cycles and dependency depth >3 are rejected. Source: app/Domains/Forms/Services/FormValidationService.php.
- **form_questions.validation_rules:** nullable object with supported numeric min_length/max_length/min/max, optional regex (length ≤200 plus PCRE match/depth limits), and date min_date/max_date used for date answers. **presentation_config:** for rating_scale, min/max bounds 1..10; other question types can use UI presentation data. Source: FormValidationService.php.
- **form_submission_revisions.snapshot_answers:** object keyed by question_key, values normalized answer scalars/arrays/booleans. It is **not** the array of {question_id, question_key, label, value} suggested by the attachment. Current canonical answers are rows in form_answers.value_text; arrays are JSON-encoded there, booleans '1'/'0'. Source: app/Domains/Forms/Services/FormSubmissionService.php.
- **audit_logs.old_values/new_values** (and previous_data/new_data): nullable associative arrays supplied by the caller, not a single fixed JSON schema. App\Domains\Audit\Models\AuditLog recursively HMAC-redacts identity, password/token, note and payment-reference keys and recognizable email/phone text on insert. event_uuid is generated. Privacy redaction may update via the controlled workflow. Do not assume every possible caller payload is safe merely because it uses this model.
- **article_revisions.snapshot:** JSON object of title, slug, excerpt, body, featured_image_path, seo_title, seo_description, canonical_url, status, published_at, locale, translation_group_id and lock_version of the former published article. Source: ArticleService::update.
- **Slot identity:** encrypted JSON, version=1, resource_id='primary_tutor', resource_date, session_type_id, start_utc/end_utc, customer_date/timezone, visitor_token, policy SHA-256 fingerprint, expires_at Unix timestamp. It is an opaque Crypt token, not client-authored JSON. Source: SlotResolver.php.
- **Analytics events:** metadata is an allow-listed associative map for browser events; server-side events have a broader internal set. source/medium/campaign/content/term live in dedicated columns. Source: AnalyticsService::ALLOWED_CLIENT_METADATA_KEYS and ::track.
